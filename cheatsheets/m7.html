1Structs

A struct groups related variables (members) of any types under one name, like a Python dataclass or a fixed-key dictionary.

Define, declare, initialise, access

struct Student {        // a new type
    int id;
    string name;
    char sex;
};                      // ← semicolon required

Student s1 = {12345, "Sze Ka Ka", 'F'};  // member order
Student s2 = s1;        // copy every member
s2.name = "Chan";       // dot operator
cout << s1.name;        // still "Sze Ka Ka"

2Structs and functions

Read → by value, modify → by reference

struct Circle { double x, y, r; };

double circleArea(Circle c) {                 // read only
    return 3.141592653589793 * c.r * c.r;
}
void enlargeCircle(Circle &c, double add) {   // modify
    c.r += add;
}
bool isOverlap(Circle a, Circle b) {          // yes / no
    double dx = a.x - b.x, dy = a.y - b.y;
    return sqrt(dx*dx + dy*dy) <= a.r + b.r;
}
Point input_point() {                         // return a struct
    double x, y;  cin >> x >> y;
    Point p = {x, y};
    return p;
}

Member functions

struct Circle {
    double x, y, r;
    double area() { return 3.14159 * r * r; }
    void enlarge(double add) { r += add; }
};

Circle c = {1, 1, 2};
cout << c.area();      // members used directly inside
c.enlarge(5);

Pointer to a struct

Point *q = &p;

3Classes

Data + functions, with access control

class Point {
public:                          // usable from outside
    double getX() { return x; }
    void setCoord(double s, double t) { x = s; y = t; }
private:                         // members only
    double x, y;
};

Point p1;
p1.setCoord(1, 2);
cout << p1.getX();   // OK
// p1.x = 5;          ✗ x is private

    cout << line << endl;

5istringstream: split a line

#include <sstream>
string line = "Peter 30 130.5";
istringstream iss(line);        // a stream over the string
string name; int age; double w;
iss >> name >> age >> w;         // like cin, from the string

string word;
while (iss >> word) { … }       // every word on the line

Python equivalent: name, age, w = line.split(). Common pattern: getline a whole line from the file, then pull its fields out with a fresh istringstream.

File I/O traps

  • while (!fin.eof()) usually handles the last item twice. Loop on the read itself.
  • Opening an existing file with plain ofstream wipes it. Use ios::app to keep it.
  • Always check fail() straight after opening.
  • exit(1) needs <cstdlib>.
  • Make a new istringstream per line; a used-up one reads nothing.

7Recursion

A recursive function calls itself on a smaller version of the problem. It needs a base case that stops, and a recursive case that moves toward it.

factorial(3): down, then back up

int factorial(int num) {
    if (num == 0) return 1;                  // base
    return num * factorial(num - 1);         // smaller problem
}

fib(4): the call tree (9 calls)

int fib(int n) {
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}

More from the notes

int gcd(int x, int y) {
    if (y == 0) return x;
    return gcd(y, x % y);
}
// gcd(18, 24) → gcd(24, 18) → gcd(18, 6) → gcd(6, 0) → 6

bool is_palindrome(string s) {
    if (s.length() < 2) return true;
    return s[0] == s[s.length() - 1]
        && is_palindrome(s.substr(1, s.length() - 2));
}

Tracing tips

  • Write each call on its own line, indented one step deeper.
  • Fill in return values from the bottom up.
  • Code after the recursive call runs on the way back, in reverse order.

Recursion vs iteration

Use recursion whenUse a loop when
the problem is naturally recursive (trees, divide and conquer)performance matters
the recursive version is clearerrecursion depth could be large
input size is controlleda loop is simpler

Every call uses stack memory: too many → stack overflow; no base case → infinite recursion and a crash. Anything recursive can also be written with a loop.

Module 7 traps

  • Missing ; after a struct's closing brace.
  • p.x for a variable, q->x for a pointer.
  • Accessing a private member from outside the class does not compile.
  • No base case, or a step that doesn't shrink the problem → infinite recursion.
  • return factorial(n-1); without n *, or a missing return, loses the result.
