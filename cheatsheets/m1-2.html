1Paths, directories & files

Everything is a file inside a tree that starts at root /. A full path starts with /; a relative path doesn't and is read from where you are (pwd).

The tree from the notes

2File permissions

Three owner classes (user, group, other) × three rights (read, write, execute). On a directory, r = list it, w = add/remove/rename inside it.

Reading a line of ls -l

Try it: click the bits

chmod [who][op][perms] file

whoopperms

o other= set exactlyx execute
a all three

chmod o+rx file    # several at once
chmod go-rw file   # remove from group+other

4Standard I/O, redirection & pipes

Every command gets three numbered streams (file descriptors). Redirection points them at files; a pipe | feeds one command's stdout straight into the next one's stdin, with no temp file.

The three streams

Operator table

SyntaxMeaning

5Searching: find & grep

find searches for files; grep searches inside files and prints matching lines. Use grep -E whenever the pattern uses regex symbols.

find [path] -name "pat" -type f|d

find . -name "hello.txt" -type f   # ./hello.txt
find . -name "hello.*"   -type f   # .cpp and .txt
find . -name "hello"     -type d   # directories only

. = start here and drill into every subdirectory. -type is optional.

Module 1 traps

  • uniq only removes adjacent duplicates. Use sort f | uniq for all.
  • sort is alphabetical by default: "10" sorts before "2". Add -n.
  • sort uses -t for delimiter, cut uses -d.
  • rmdir fails on a non-empty dir; use rm -rf.
  • grep is case-sensitive: 'hell' misses "Hello".
  • [a-z,A-Z] also matches a comma. Write [a-zA-Z].
  • co* = c then any o's (matches "cherries"); (co)+ repeats "co".
  • 2>&1 goes after the stdout redirect: cmd > f 2>&1.

7Script basics

A shell script (.sh) is a text file of commands. Bash is interpreted: no compile step, quick to edit, slower to run. Write it on Linux or save with LF line endings; Windows CRLF breaks it.

hello.sh, start to finish

#!/bin/bash          # shebang: which program runs this
# a comment
echo "Hello world!"
echo -n "no newline "   # -n: no trailing newline
$ chmod u+x hello.sh   # make executable
$ ./hello.sh           # ./ = look in current dir
$ which -a bash        # find bash's path(s)

Typical use: compile + run + show

#!/bin/bash
g++ add.cpp -o add
./add < input.txt > output.txt
cat output.txt

Groups commands you'd otherwise retype every time.

8Variables, quoting & strings

Bash has one type: string. Names use letters, digits and _, and are case-sensitive. Set without $, read with $.

Set, read, input

pet="dog"        # NO spaces around =
echo $pet        # dog
read name        # set from user input (no $)
echo "Hello $name"

Three ways to quote

StyleBehaviour
a=catunquoted: single word only. a=Apple pie → "pie: command not found"
'…'literal; $name stays as text
"…"expands $var, \ escapes, `cmd`
name="Apple"
echo 'Hello, $name'    # Hello, $name
echo "Hello, $name"    # Hello, Apple
echo "\$name = $name"  # $name = Apple

Command substitution: backquotes

a="`cat file.txt`"
echo $a       # Apple Banana Cherry (one line)
echo "$a"     # keeps the newlines
b="`wc -l file.txt | cut -d\" \" -f1`"
echo "There are $b lines"

Inner " must be escaped as \" inside a double-quoted string.

9Flow of control: if & for

Spaces inside the brackets are mandatory: [ "$a" == "b" ]. Quote string variables so values with spaces still compare correctly.

Syntax

if [ cond1 ]
then
  echo "1 met"
elif [ cond2 ]
then
  echo "2 met"
else
  echo "none"
fi
list="1 2 3 4 5"      # split on spaces
for i in $list
do
  echo "iteration $i"
done

String tests

TestTrue iff
[ "$s" ]length non-zero
[ "$a" == "$b" ]equal
[ "$a" != "$b" ]different
[ "$a" \> "$b" ]a sorts after b
[ "$a" \< "$b" ]a sorts before b

\> is escaped so it isn't treated as redirection.

Number tests

-eq =-ne ≠-lt <
-le ≤-gt >-ge ≥

File tests

TestTrue iff
[ -e $f ]exists
[ -f $f ]is a regular file
[ -d $f ]is a directory
[ -s $f ]size > 0
[ -r $f ]readable
[ -w $f ]writable
[ -x $f ]executable

Permission tests apply to whoever runs the script.

The pattern the checkpoints keep using: compile, check, run

#!/bin/bash
if [ -e hello.cpp ]
then
  g++ hello.cpp -o hello 2> error.txt
  if [ -e hello ]          # exe exists → compiled OK
  then
    ./hello
  else
    echo "Compilation failed!"
    cat error.txt
  fi
else
  echo "hello.cpp not found!"
fi
#!/bin/bash
# back up every .cpp file
list="`ls *.cpp`"
for fileName in $list
do
  cp $fileName "$fileName.backup"
done

# silence a command, report errors on stderr
cp file123 fileabc 1>/dev/null 2>&1
if [ -e fileabc ]
then echo "Copy successful"
else echo "$0: Oops. Copy failed :(" >&2
fi

/dev/null is the bin for unwanted output. echo … >&2 writes to stderr, so ./script 2> err.txt captures it. While-loops and functions are out of syllabus.

Shell-script traps

  • x = 5 is wrong; x=5 is right.
  • [$a == b] is wrong; you need spaces: [ $a == b ].
  • == compares text: "05" ≠ "5". -eq compares numbers: 05 = 5.
  • Single quotes never expand $var.
  • read name, not read $name.
  • $10 is $1 + "0". Use ${10}.
  • String index starts at 0; cut/sort fields start at 1.
  • Forgot chmod u+x? → "Permission denied".

11Branching & merging · not examined in the 2026 final

A branch is a pointer to its latest commit. HEAD marks where you are now. The notes' example: create BugFix, commit on both branches, merge master into BugFix first (safer), then fast-forward master.

Git traps

  • git commit saves to your local repo only. Nobody sees it until you git push.
  • Push rejected? Someone pushed first. git pull, merge, then push again.
  • git branch b doesn't switch you to b. Use checkout or checkout -b.
  • Fast-forward creates no commit; a real merge does (give it -m).
  • git diff with no output means working dir = staging.
  • -d deletes merged branches; -D forces unmerged ones.
