1C vs C++

C is C++'s lower-level predecessor: no classes, no STL, no namespaces, no iostream. Operating systems and networking libraries are mostly C. Any C program is also valid C++, not the other way round.

2printf: formatted output

Put a conversion specifier in the string for each value; values fill them in order. The specifier must match the type or the output is garbage. · marks a space.

3scanf: formatted input

int a;  float b;  double d;  char c;  char name[20];

scanf("%d%f", &a, &b);    // give ADDRESSES: &
scanf("%lf", &d);          // double needs %lf
scanf(" %c", &c);          // space skips leftover newline
scanf("%s", name);         // array name is already an address
printf("Product = %g\n", a * b);

char n[20], p[20]; int sal;
scanf("%s%s%d", n, p, &sal);   // several at once

printf takes values; scanf takes addresses so it can write into your variables. %s reads one word (stops at whitespace); fgets(s, 20, stdin) reads a whole line and keeps the '\n'.

printf / scanf traps

  • scanf("%d", a) without & → crash.
  • scanf("%s", &name): no & needed for an array.
  • %f in scanf for a double reads wrongly: use %lf.
  • Specifier must match the type in printf, or the value is garbage.
  • %f always shows 6 decimals unless you write %.2f or use %g.
  • No endl in C.

5Pass by reference with pointers, arrays

Three swaps (from the notes)

void swap1(double a, double b);    // by value: no effect
void swap2(double &a, double &b);  // C++ only: gcc rejects it
void swap3(double *a, double *b) { // C: pass addresses
    double temp = *a;
    *a = *b;
    *b = temp;
}
swap3(&x, &y);

Arrays are passed as addresses

void salary_increase(int sal[]) {
    for (int i = 0; i < 4; i++)
        sal[i] = sal[i] * 1.1;
}
// same thing, pointer style
void salary_increase(int *sal) {
    for (int i = 0; i < 4; i++) {
        *sal = *sal * 1.1;
        sal++;
    }
}

sal[i] is *(sal + i). Changes inside reach the caller's array.

6malloc and free

#include <stdlib.h>
int size = 10;
int *a = (int *)malloc(size * sizeof(int));
if (a != NULL) {          // malloc returns NULL on failure
    for (int i = 0; i < size; i++) a[i] = i;
    free(a);              // exactly once
}

8GDB, the GNU debugger

Print statements clutter output and get forgotten. A debugger lets you pause at a breakpoint, step line by line and watch variables, which is how you find runtime errors like segmentation faults.

Commands

ShortLongDoes
rrunstart the program
b 8break 8breakpoint at line 8
clearremove a breakpoint
nnextrun the next line
p iprint ishow a variable's value
llistshow the source code
qquitleave gdb

Finding the segfault (notes' example)

Node *current = NULL;
for (int i = 0; i < 5; i++) {
    Node *_newNode = new Node;
    _newNode->id = i;
    _newNode->next = NULL;
    current->next = _newNode;   // line 15: bug
}
$ gdb hello
(gdb) r
Program received signal SIGSEGV, Segmentation fault.
0x... in main () at hello.cpp:15
15      current->next = _newNode;
(gdb) p i
$1 = 0                      ← first iteration
(gdb) p current
$2 = (Node *) 0x0           ← NULL: that's the bug
(gdb) q

SIGSEGV = invalid memory access. Print every pointer on the faulting line; the one showing 0x0 is NULL.

GDB notes

  • Without -g, gdb can't show line numbers or variable names.
  • At a breakpoint, that line has not run yet: variables it sets still hold garbage.
  • "No symbol "i" in current context" = i isn't declared at this point (e.g. before its loop).
  • Online alternative with a visual panel: onlinegdb.com.
