1One program, three files

Move a function into its own .cpp, and put its declaration in a .h that other files include. Each .cpp is compiled on its own without knowing about the others, which is why the header is needed.

gcd.h — declaration

#ifndef GCD_H     // if not defined yet…
#define GCD_H     // …define it now
int gcd(int a, int b);
#endif

gcd.cpp — definition

#include "gcd.h"
int gcd(int a, int b) {
    while (a != b) {
        if (a > b) a -= b;
        else       b -= a;
    }
    return a;
}

gcd_main.cpp — uses it

#include <iostream>
#include "gcd.h"
using namespace std;
int main() {
    int a, b;
    cin >> a >> b;
    cout << "GCD is " << gcd(a, b);
}

Compiling it: all at once vs separately

CommandDoes
g++ gcd_main.cpp gcd.cpp -o gcdcompile both and link in one go
g++ -c gcd.cppstages 1–3 only → gcd.o (object code)
g++ -c gcd_main.cpp→ gcd_main.o
g++ gcd.o gcd_main.o -o gcdstage 4: link the objects into the executable

Why bother: compile and test files independently; after an edit, recompile only that file and relink (a full Linux build takes hours); ship gcd.h + gcd.o without revealing your source.

2The four stages of compilation

3Headers and include guards

#include forms

#include <iostream>search the system / standard library
#include "gcd.h"search your project folder first

Either way the pre-processor pastes the file's text in at compile time. Headers are never compiled on their own, and never appear in g++ -c.

Why the guard

If main.cpp includes a.h and b.h, and both include gcd.h, the declarations would be pasted twice. The guard makes the second copy empty: GCD_H is already defined, so everything up to #endif is skipped.

4Makefile rules

The file must be called Makefile (or makefile), no extension. It is a list of rules; comments start with #.

How make decides

  1. Look at the target's dependencies. Make any that are out of date first (recursively).
  2. A file is out of date if it doesn't exist, or it is older than any of its dependencies (modification time).
  3. If the target is out of date, run its commands. If it is up to date, do nothing.

Result: the minimum number of files gets rebuilt.

Plain Makefile

gcd_main: gcd.o gcd_main.o
	g++ gcd.o gcd_main.o -o gcd_main

gcd.o: gcd.cpp gcd.h
	g++ -c gcd.cpp

gcd_main.o: gcd_main.cpp gcd.h
	g++ -c gcd_main.cpp
$ make gcd_main
g++ -c gcd.cpp
g++ -c gcd_main.cpp
g++ gcd.o gcd_main.o -o gcd_main

Read the graph bottom-up

  • Bottom row: files you write (.cpp, .h).
  • Middle: one .o per .cpp. Its arrows come from that .cpp and every header it includes.
  • Top: the executable, from all the .o files.
  • Edit census.cpp → rebuild census.o, relink.
  • Edit Country.h → rebuild census.o and Country.o, relink.

6Variables, automatic variables and phony targets

Automatic variables

VarMeansIn census.o: census.cpp a.h b.h
$@the targetcensus.o
$^the whole dependency listcensus.cpp a.h b.h
$<the left-most dependencycensus.cpp

Your own variables: NAME = value, read with $(NAME).

g++ -c $<          # compile rule: just the .cpp
g++ $^ -o $@       # link rule: all the .o files

Complete Makefile from the notes

FLAGS = -pedantic-errors -std=c++11

gcd.o: gcd.cpp gcd.h
	g++ $(FLAGS) -c $<

gcd_main.o: gcd_main.cpp gcd.h
	g++ $(FLAGS) -c $<

gcd_main: gcd.o gcd_main.o
	g++ $(FLAGS) $^ -o $@

clean:
	rm -f gcd_main gcd.o gcd_main.o gcd.tgz

tar:
	tar -czvf gcd.tgz *.cpp *.h

.PHONY: clean tar

Phony targets

clean and tar are fake targets: no file is produced, they are shortcuts for a command. make clean deletes the build files; make tar archives the sources.

Pitfall: if a file named clean exists, make says 'clean' is up to date and does nothing. Listing it under .PHONY makes the command run every time.

tar flagMeans
-ccreate an archive
-zcompress with gzip
-vverbose: list files as they go in
-f gcd.tgzarchive file name

7Exam recipe: write a Makefile from #includes

Steps

  1. List every .cpp. Each gives one X.o: X.cpp … rule.
  2. For each .cpp, add every header it includes, and every header those headers include (transitively).
  3. Executable rule first: prog: all the .o files.
  4. Commands: g++ -c X.cpp for objects, g++ a.o b.o -o prog to link.
  5. Add clean and .PHONY: clean if asked.
  6. Mark each command line's TAB clearly.

Module 4 traps

  • Spaces instead of a TAB before a command → "missing separator".
  • .h files go in dependency lists, never in g++ -c.
  • $^ in a compile rule passes the headers to g++ too: use $<.
  • Forgetting a transitive header: if thing.h includes gadget.h, thing.o depends on gadget.h.
  • The first rule is the default goal: put the executable first.
  • Name the file exactly Makefile, no .txt.
